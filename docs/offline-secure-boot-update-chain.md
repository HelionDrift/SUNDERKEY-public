# Offline Secure Boot Update Chain

This R0 component projects caller-supplied Secure Boot state, ordered boot-chain declarations, and proposed version changes for `AOE-GD-D18-S03`. It checks whether a reported Secure Boot flag matches a supplied expectation, whether each declared predecessor matches the supplied list order, and whether a declared loaded image was also declared rejected while Secure Boot was reported enabled. It compares proposed UINT32 versions with supplied rollback floors for artifacts named in the chain. Every mismatch is an unsigned review candidate, not an observed platform defect. A missing target, unknown declared validation, or incomplete chain remains unknown.

The [UEFI Specification 2.10, Secure Boot and Driver Signing](https://uefi.org/specs/UEFI/2.10/32_Secure_Boot_and_Driver_Signing.html) describes UEFI image validation and its signature databases. The [UEFI Specification 2.10, Firmware Update and Reporting](https://uefi.org/specs/UEFI/2.10/23_Firmware_Update_and_Reporting.html) defines a `LowestSupportedFwVersion` field for ESRT resources. [NIST SP 800-193](https://csrc.nist.gov/pubs/sp/800/193/final) provides the broader platform firmware resiliency context. The component's ordered predecessor rule and expected Secure Boot flag are local, caller-supplied declaration conventions, not UEFI conformance rules. Its per-artifact rollback floor is a generic supplied number, not a claim that every boot-chain artifact maps to an ESRT resource.

The model accepts at most 64 boot-chain entries and 64 proposed updates. It never reads UEFI variables or event logs, parses a boot image or capsule, verifies a certificate or signature, contacts a platform, attempts an update, or proves Secure Boot or rollback enforcement. The unsigned report can only be verified by replay against a separately retained original model. It grants no finding, qualification, or positive-use authority.
